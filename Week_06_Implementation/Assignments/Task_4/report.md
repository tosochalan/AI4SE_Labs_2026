The chooser ranks stored chunk vectors by cosine similarity to the task embedding and returns the top *n* results. Cosine similarity compares vector direction, so it remains appropriate if vectors are not exactly unit-normalized. Ties preserve input order, and malformed or dimension-mismatched vectors are rejected instead of silently producing misleading rankings. The CLI embeds task text with the same Task 3 TF-IDF configuration, then joins result IDs to `structure.json` to include source text. The ranking function also accepts an already-created query vector for reuse in code or tests.

The CLI also adds a small metadata reranking boost when query terms match a chunk's symbol name or source path. An exact symbol-name match receives the strongest boost, helping queries such as `BulkDiscountPricing` favor the implementation class over tests that merely mention pricing. The result retains the original cosine `similarity` and reports the final combined `score`; callers that provide only a vector still get cosine-only ranking.
